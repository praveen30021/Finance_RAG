One line before you start

All three are Gradient Boosting on Decision Trees (GBDT). The maths of boosting is the same in all three. They differ only in three things: (1) how a tree finds the best split, (2) how the tree grows, and (3) what extra problem they fix — LightGBM fixes speed, CatBoost fixes categorical features and target leakage.

Part 1

CatBoost

Categorical Boosting — Yandex, 2017

1Summary of All Formulas

A. Handling Categorical Features

Greedy Target Statistic (plain mean / target encoding):

$$\hat{x}^k_i=\frac{\sum_{j=1}^{n}\mathbb{1}\{x^k_j=x^k_i\}\cdot y_j+a\,P}{\sum_{j=1}^{n}\mathbb{1}\{x^k_j=x^k_i\}+a}$$

Ordered Target Statistic (what CatBoost actually uses):

$$\hat{x}^k_i=\frac{\sum_{x_j\in\mathcal{D}_i}\mathbb{1}\{x^k_j=x^k_i\}\cdot y_j+a\,P}{\sum_{x_j\in\mathcal{D}_i}\mathbb{1}\{x^k_j=x^k_i\}+a}, \qquad \mathcal{D}_i=\{x_j:\sigma(j)\lt\sigma(i)\}$$

\(\sigma\) = a random permutation (the artificial "time"), \(\mathcal{D}_i\) = only the rows that come before row \(i\), \(P\) = prior (usually the mean of \(y\) over the whole training set), \(a\gt 0\) = smoothing weight.

B. Ordered Boosting

Ordinary gradient boosting (biased):

$$g_i=-\left.\frac{\partial L(y_i,s)}{\partial s}\right|_{s=F^{t-1}(x_i)}\qquad\text{(}F^{t-1}\text{ has already seen } y_i\text{)}$$

Ordered boosting (unbiased):

$$g_i=-\left.\frac{\partial L(y_i,s)}{\partial s}\right|_{s=M_{\sigma(i)-1}(x_i)}$$

\(M_{\sigma(i)-1}\) is a supporting model trained only on the rows before \(i\), so it has never seen \(y_i\).

C. Tree and Model (same as gradient boosting)

Leaf value (Newton step):

$$w_j=-\frac{\sum_{i\in I_j}g_i}{\sum_{i\in I_j}h_i+\lambda}=-\frac{G_j}{H_j+\lambda}$$

Split gain:

$$\text{Gain}=\frac{1}{2}\left[\frac{G_L^2}{H_L+\lambda}+\frac{G_R^2}{H_R+\lambda}-\frac{G_P^2}{H_P+\lambda}\right]$$

Oblivious tree leaf index (all splits of one level are the same):

$$\text{leaf}(x)=\sum_{d=0}^{D-1}2^{\,d}\cdot\mathbb{1}\{x^{f_d}\gt t_d\}$$

Model update:

$$F_m(x)=F_{m-1}(x)+\eta\cdot T_m(x)$$

2What is CatBoost?

CatBoost = Categorical + Boosting. It is gradient boosting on decision trees, made by Yandex in 2017. The boosting part is nothing new — the new part is that it solves two problems that every other GBDT library had:

  1. Categorical features. Normal libraries need you to encode city, product-id, user-id yourself. One-hot blows up the memory, and mean (target) encoding leaks the target. CatBoost does the encoding inside the model, in a leak-free way.
  2. Prediction shift (a hidden kind of leakage in boosting itself). In normal boosting, the residual of a row is calculated using a model that was trained on that same row. So the residuals are slightly "too good" on train and the model is biased. CatBoost fixes this with ordered boosting.
The one-line answer

"CatBoost is gradient boosting that handles categorical features internally using ordered target statistics, removes the bias of boosting using ordered boosting, and builds symmetric (oblivious) trees which make prediction extremely fast."

2.1The Big Picture

The workflow is the same five steps as any boosting model:

  1. Start with a base model (mean of \(y\), or log-odds for classification).
  2. Calculate the errors (gradients / residuals) — but using ordered boosting.
  3. Build a decision tree on those errors — but the tree is symmetric.
  4. Add the tree to the model after multiplying by the learning rate \(\eta\).
  5. Repeat.
The major twist

In XGBoost the twist was the Similarity Score. In CatBoost the twist is in two other places: how the categorical columns become numbers (ordered target statistics), and which model is used to compute the residual (ordered boosting).

3Core Concepts

1. Target Statistic (TS)

Replacing a category (like "Delhi") by a number calculated from the target \(y\) of the rows having that category. Also called target encoding or mean encoding.

2. Target Leakage

When the value of \(y_i\) of the same row is used to build the feature of that row. The model then looks great on training data and fails on test data.

3. Ordered Principle

Pretend the dataset arrived one row at a time (a random permutation \(\sigma\) is the fake "time"). To calculate anything for row \(i\), use only the rows that came before it. This single idea is used twice in CatBoost: for the encoding (ordered TS) and for the residuals (ordered boosting).

4. Oblivious (Symmetric) Tree

A tree where every node at the same depth uses the same feature and the same threshold. So a tree of depth 6 has only 6 split decisions and \(2^6=64\) leaves.

5. Feature Combinations

CatBoost automatically creates new categorical features by joining existing ones, e.g. city × device, and encodes the combination as one category. This captures interaction without you writing it.

6. Learning Rate and Regularisation

\(\eta\) (learning rate, default about 0.03–0.1) and \(\lambda\) (l2_leaf_reg, default 3) work exactly like in XGBoost.

4Problem 1: Categorical Features

4.1Why the Usual Methods Fail

MethodWhat it doesWhy it fails
One-Hot EncodingOne new 0/1 column per categoryA user-id column with 1 lakh categories creates 1 lakh columns. Memory blows up and every split becomes very weak.
Label EncodingDelhi=1, Mumbai=2, Pune=3Creates a fake order. The tree will think Pune > Mumbai > Delhi, which has no meaning.
Target (Mean) EncodingReplace the category by the mean \(y\) of that categoryVery powerful, but it leaks the target — explained below.

4.2Target Statistic with Smoothing

The basic idea of target encoding is simple: a category is useful if the target behaves differently inside it. So replace the category by its average target:

$$\hat{x}^k_i=\frac{\sum_{j=1}^{n}\mathbb{1}\{x^k_j=x^k_i\}\cdot y_j}{\sum_{j=1}^{n}\mathbb{1}\{x^k_j=x^k_i\}}=\frac{\text{sum of }y\text{ in that category}}{\text{count of that category}}$$

Problem: if a category appears only twice, this average is pure noise. So we pull it towards a prior \(P\) (the global mean of \(y\)) with a weight \(a\):

Formula / Result: Smoothed Target Statistic
$$\hat{x}^k_i=\frac{\sum_{j}\mathbb{1}\{x^k_j=x^k_i\}\cdot y_j+a\,P}{\sum_{j}\mathbb{1}\{x^k_j=x^k_i\}+a}$$

Read it as: (sum of y in the category + a × prior) / (count + a). If the count is large, \(a\,P\) hardly matters and we get the real mean. If the count is 1 or 2, the value stays close to the prior. This is the same idea as Laplace smoothing.

4.3Derivation: Why Plain Target Encoding Leaks

Step 1: Take the worst case.

Suppose a categorical feature where every row has its own unique category (like an order-id). Take \(a=0\) for a moment. For row \(i\), the only row having that category is row \(i\) itself. So the formula gives:

$$\hat{x}^k_i=\frac{1\cdot y_i}{1}=y_i$$

Step 2: See what the tree does with it.

The feature is now exactly the target. Suppose the target is 0/1. A single split at threshold \(t=0.5\) separates the data perfectly:

$$\hat{x}^k_i\lt 0.5 \Rightarrow y_i=0,\qquad \hat{x}^k_i\gt 0.5\Rightarrow y_i=1$$

Step 3: See what happens on test data.

A new row has a category that was never seen. Its encoded value becomes the prior \(P\) for everyone. So every test row goes to the same side of the split and the accuracy drops to the base rate.

Key Insight

Training error \(\to 0\), test error \(\to\) random. The feature carried the answer inside it. This is target leakage. Formally, the problem is that \(\hat{x}_i\) is computed using \(y_i\), so \(\;\mathbb{E}[\hat{x}^k\mid y]\) is different on train and on test. CatBoost calls this a violation of the property \(P1\): the expected value of the encoding must be the same for training and test examples.

4.4Attempt 1: Holdout TS

Split the data into two parts: use part \(\mathcal{D}_0\) to compute the encoding and part \(\mathcal{D}_1\) to train. No leakage, because \(y_i\) of a training row is never used in its own encoding.

Why it is rejected: you lose data twice — the encoding is computed on fewer rows (noisy), and the model trains on fewer rows (weaker). It breaks a second property \(P2\): use all the data effectively.

4.5Attempt 2: Leave-One-Out TS (and why it also leaks)

Natural idea: for row \(i\), use all rows except row \(i\):

$$\hat{x}^k_i=\frac{\sum_{j\neq i}\mathbb{1}\{x^k_j=x^k_i\}\cdot y_j+a\,P}{\sum_{j\neq i}\mathbb{1}\{x^k_j=x^k_i\}+a}$$

It looks safe, but it is not. Take the opposite extreme case: one single category for all \(n\) rows, target is 0/1, and let \(n^{+}\) be the number of ones. With \(a=0\):

$$\hat{x}^k_i=\frac{n^{+}-y_i}{\,n-1\,}$$

Now look carefully. The value is different for a row with \(y_i=0\) and a row with \(y_i=1\):

$$y_i=0\;\Rightarrow\;\hat{x}_i=\frac{n^{+}}{n-1},\qquad y_i=1\;\Rightarrow\;\hat{x}_i=\frac{n^{+}-1}{n-1}$$

So a split at the threshold \(t=\dfrac{n^{+}-0.5}{n-1}\) again separates the two classes perfectly on the training set, even though the feature is a single constant category and carries no information at all.

Key Insight

Leave-one-out does not use \(y_i\) directly, but \(y_i\) still subtracts itself out of the numerator, and the tree can read that subtraction. Any scheme where the encoding of row \(i\) depends on \(y_i\) — even negatively — leaks.

4.6The Solution: Ordered Target Statistics

CatBoost borrows the idea from online learning: a model that sees data one example at a time can never cheat, because the future does not exist yet. But our dataset has no time column, so CatBoost invents one — a random permutation \(\sigma\).

Formula / Result: Ordered Target Statistic
$$\hat{x}^k_i=\frac{\sum_{x_j\in\mathcal{D}_i}\mathbb{1}\{x^k_j=x^k_i\}\cdot y_j+a\,P}{\sum_{x_j\in\mathcal{D}_i}\mathbb{1}\{x^k_j=x^k_i\}+a}, \qquad\mathcal{D}_i=\{x_j:\sigma(j)\lt\sigma(i)\}$$

Only the history of row \(i\) is used. Row \(i\)'s own target never enters its own encoding, so there is no leakage. All rows still get used (every row is in the history of the later rows), so no data is wasted.

Two practical details:

  • The first row has an empty history, so it just gets the prior \(P\). Early rows have high variance, later rows are stable.
  • To stop the early rows from always being noisy, CatBoost uses several different permutations — a new one for each tree. This averages out the variance.

Small numeric example

Prior \(P=0.5\), smoothing \(a=1\). Permutation order is simply row 1, 2, 3, 4, 5.

#cityyHistory of same cityOrdered TS calculationValue

4.7Feature Combinations

A single categorical column may be useless alone but strong in combination (for example city alone and device alone say little, but Delhi + iPhone says a lot). CatBoost builds these greedily:

  • At the first split, only the single categorical features are considered.
  • From the next split onwards, CatBoost joins the categorical features already used in the current tree with all other categorical features, treats the pair as one new category, encodes it with ordered TS, and considers it as a candidate split.
  • All possible combinations would be \(2^{\,\#cat}\), so this greedy approach keeps it affordable.
Note

For features with very few categories (default one_hot_max_size = 2) CatBoost simply uses one-hot encoding, because the leakage problem is small when the categories are few and large.

5Problem 2: Prediction Shift and Ordered Boosting

5.1What is Prediction Shift?

This is the deeper problem, and it exists in every boosting library, not only when categorical features are present.

In stage \(t\), ordinary gradient boosting computes the gradient of every training row using the current model \(F^{t-1}\):

$$g_i=-\left.\frac{\partial L(y_i,s)}{\partial s}\right|_{s=F^{t-1}(x_i)}$$

But \(F^{t-1}\) was trained on the whole training set, including row \(i\) itself. So the model already partly memorised \(y_i\), which makes \(F^{t-1}(x_i)\) unusually close to \(y_i\), which makes the gradient \(g_i\) unusually small.

Key Insight

The distribution of the gradient on a training point, \(g(x_i,y_i)\mid x_i\), is not the same as the distribution on a test point, \(g(x,y)\mid x\). This difference is called prediction shift. The trees are therefore fitted to slightly wrong targets, and the final model is biased. The size of the bias is of order \(1/n\), so it hurts most on small datasets.

It is the same disease as target leakage in section 4, just one level higher: there, the feature used \(y_i\); here, the residual uses \(y_i\).

5.2Derivation Sketch of the Bias

Step 1.

Let the true (unknown) best function be \(f\). After stage \(t-1\) we have \(F^{t-1}\). Ideally we want the next tree \(h^t\) to approximate the true gradient:

$$h^{t}\approx \arg\min_h\;\mathbb{E}_{x,y}\big[(-g(x,y)-h(x))^2\big]$$

Step 2.

In practice we cannot take an expectation over the unknown distribution, so we replace it with the average over the training rows:

$$h^{t}=\arg\min_h\;\frac{1}{n}\sum_{i=1}^{n}\big(-g(x_i,y_i)-h(x_i)\big)^2$$

Step 3.

This swap is only valid if \(g(x_i,y_i)\mid x_i\) has the same distribution as \(g(x,y)\mid x\). It does not, because \(F^{t-1}\) saw \((x_i,y_i)\). Therefore

$$\mathbb{E}\big[g(x_i,y_i)\mid x_i\big]\neq\mathbb{E}\big[g(x,y)\mid x=x_i\big]$$

and every tree inherits a small bias, which then accumulates over hundreds of trees.

5.3The Solution: Ordered Boosting

Use the same ordered trick again. Fix a random permutation \(\sigma\). For every row \(i\), compute its residual using a model that was trained only on the rows before \(i\).

Formula / Result: Ordered Boosting Gradient
$$g_i=-\left.\frac{\partial L(y_i,s)}{\partial s}\right|_{s=M_{\sigma(i)-1}(x_i)}$$

\(M_k\) = a supporting model trained on the first \(k\) rows of the permutation. Since \(M_{\sigma(i)-1}\) never saw \(y_i\), the gradient of row \(i\) is unbiased.

The algorithm in words

Choose a random permutation sigma of the n training rows.
Keep n supporting models  M_0, M_1, ..., M_(n-1).
   M_k  is trained only on the first k rows.

For each boosting round t:
    For every row i:
         residual_i  =  y_i  -  M_(sigma(i)-1) (x_i)      # unbiased residual
    Build tree T_t on these residuals (structure is shared by all models)
    Update every supporting model M_k with the part of T_t it is allowed to see
Final model = sum of all trees x learning rate
Why this is practical

Keeping \(n\) separate models would cost \(O(n^2)\) in time and memory. CatBoost keeps only \(\log_2 n\) supporting models (for sizes \(1,2,4,8,\dots\)) and uses a different permutation for each tree. That brings the cost back to the same order as ordinary boosting.

Plain mode vs Ordered mode

boosting_type='Ordered' uses the full scheme above — better on small datasets (roughly under 50k rows) but slower. boosting_type='Plain' is ordinary boosting (still with ordered TS for the categories) and is the default on large data because the \(1/n\) bias is then negligible.

6Oblivious (Symmetric) Trees

In XGBoost and LightGBM, every node can choose its own feature and threshold. In CatBoost, all nodes at the same depth share one split.

Figure 6.1 — A depth-2 normal tree has 3 different splits; the oblivious tree has only 2.
Formula / Result: Leaf index of an oblivious tree
$$\text{leaf}(x)=\sum_{d=0}^{D-1}2^{\,d}\cdot\mathbb{1}\{x^{f_d}\gt t_d\}\;\in\;\{0,1,\dots,2^{D}-1\}$$

Each level contributes one bit. The prediction is then just leaf_values[index] — a single array lookup, no branching.

AdvantageReason
Very fast predictionDepth \(D\) comparisons produce a \(D\)-bit number; the leaf value is one array lookup. No if-else chain, CPU-friendly, easy to vectorise. CatBoost inference is often several times faster than XGBoost.
Acts as regularisationFar fewer possible tree structures, so the tree cannot chase noise. This is one reason CatBoost often works well with default settings.
Balanced and smallAlways exactly \(2^D\) leaves, so the model size is predictable.
DisadvantageLess flexible than a free-form tree, so CatBoost sometimes needs more trees to reach the same accuracy.

7.5Build a Symmetric Tree of Depth 1

Because the tree is oblivious, we need only one split for the whole level. Try the candidate CGPA < 7.5:

Left (CGPA < 7.5) = rows 2, 4 with residuals \(\{-1,-3\}\); Right = rows 1, 3 with residuals \(\{+1,+3\}\).

Using \(G=\sum g_i=-\sum r_i\), \(H=\sum h_i=\) count, \(\lambda=0\):

$$\text{Gain}=\frac{1}{2}\left[\frac{G_L^2}{H_L}+\frac{G_R^2}{H_R}-\frac{G_P^2}{H_P}\right] =\frac{1}{2}\left[\frac{4^2}{2}+\frac{(-4)^2}{2}-\frac{0^2}{4}\right]=\frac{1}{2}\,[8+8-0]=8$$

Now try city_encoded < 5.25: Left = rows 1, 2, 4 (values 5.00, 5.00, 4.50) with residuals \(\{+1,-1,-3\}\), Right = row 3 with \(\{+3\}\).

$$\text{Gain}=\frac{1}{2}\left[\frac{3^2}{3}+\frac{(-3)^2}{1}-0\right]=\frac{1}{2}\,[3+9]=6$$

The CGPA split wins (gain 8 > 6), so the whole level uses CGPA < 7.5.

9.2Practical Points

  • Do not encode the categorical columns yourself. Pass the raw strings and list them in cat_features. If you label-encode first, you lose the whole benefit.
  • Categorical columns must be str or int — float categories throw an error.
  • CatBoost has the best "works well without tuning" reputation of the three, mainly because of the oblivious trees and the ordered scheme.
  • It also supports text features and embedding features, and has GPU training.
  • Missing values: numeric NaN is handled automatically (sent to one side); missing categories are treated as their own category.

LightGBM

Light Gradient Boosting Machine — Microsoft, 2017

1Summary of All Formulas

A. Split Gain (same boosting maths as XGBoost)
$$\text{Gain}=\frac{1}{2}\left[\frac{G_L^2}{H_L+\lambda}+\frac{G_R^2}{H_R+\lambda}-\frac{G_P^2}{H_P+\lambda}\right]-\gamma, \qquad w_j=-\frac{G_j}{H_j+\lambda}$$

Variance gain used in the LightGBM paper (gradients only):

$$V_{j}(d)=\frac{1}{n}\left[\frac{\big(\sum_{x_i\in O:\;x_{ij}\le d}g_i\big)^2}{n_{l}(d)}+\frac{\big(\sum_{x_i\in O:\;x_{ij}\gt d}g_i\big)^2}{n_{r}(d)}\right]$$
B. Histogram Algorithm

Each feature value is replaced by a bin index:

$$\text{bin}(x_{ij})=k\quad\text{if}\quad b_{k-1}\lt x_{ij}\le b_k,\qquad k=1\dots K\;(K=255\text{ by default})$$

Histogram of a node: for every bin \(k\), store \(\;\sum g_i,\;\sum h_i,\;\text{count}\).

Histogram subtraction trick:

$$\text{Hist}_{\text{sibling}}=\text{Hist}_{\text{parent}}-\text{Hist}_{\text{child}}$$

Cost: building \(O(\#data\times\#feature)\), split search \(O(\#bin\times\#feature)\).

C. GOSS — Gradient-based One-Side Sampling

Keep the top \(a\times 100\%\) rows by \(|g|\) (set \(A\)), randomly sample \(b\times 100\%\) of the rest (set \(B\)), and amplify the sampled small-gradient rows:

$$\tilde{V}_j(d)=\frac{1}{n}\left[\frac{\Big(\sum_{x_i\in A_l}g_i+\frac{1-a}{b}\sum_{x_i\in B_l}g_i\Big)^2}{n_l(d)} +\frac{\Big(\sum_{x_i\in A_r}g_i+\frac{1-a}{b}\sum_{x_i\in B_r}g_i\Big)^2}{n_r(d)}\right]$$

The amplification constant:

$$\boxed{\;\text{weight}=\frac{1-a}{b}\;}$$
D. EFB — Exclusive Feature Bundling

Two features are exclusive if they are rarely non-zero at the same time. Merge them with an offset:

$$x_{\text{bundle}}=\begin{cases}x_A & \text{if } x_A\neq 0\\[2pt] x_B+\text{offset}_A & \text{if } x_A=0\end{cases}, \qquad \text{offset}_A=\max(x_A)$$

Complexity drops from \(O(\#data\times\#feature)\) to \(O(\#data\times\#bundle)\).

E. Leaf-wise Growth

At every step, split the one leaf in the whole tree that gives the biggest gain:

$$\text{leaf}^{*}=\arg\max_{\text{all current leaves}}\;\text{Gain}(\text{leaf})$$

Controlled by num_leaves, with the safety relation \(\;\texttt{num\_leaves}\le 2^{\texttt{max\_depth}}\).

2What is LightGBM?

LightGBM = Light Gradient Boosting Machine, from Microsoft (2017). "Light" means fast to train and small in memory. The accuracy is about the same as XGBoost — the contribution is speed.

It achieves this with four ideas:

  1. Histogram-based split finding — put continuous values into 255 bins instead of sorting them.
  2. GOSS — drop most of the rows that are already well predicted.
  3. EFB — merge sparse features that are never non-zero together.
  4. Leaf-wise tree growth — grow where the loss drops most, instead of level by level.
The one-line answer

"LightGBM is gradient boosting made fast. It bins features into histograms, uses GOSS to keep only the informative rows, uses EFB to merge sparse features, and grows trees leaf-wise instead of level-wise. The result is the same accuracy as XGBoost with much less time and memory."

2.1The Big Picture

The boosting loop is identical to XGBoost: base model → gradients and Hessians → build a tree → add \(\eta\times\) tree → repeat. The leaf value and the gain formula are the same. Only the way the tree is built changes.

3Core Concepts

1. Bin / Histogram

A feature's continuous values are grouped into at most max_bin (255) buckets. The tree then only considers 254 candidate thresholds instead of every unique value.

2. Gradient as "how wrong we still are"

A row with a large \(|g|\) is still badly predicted and is informative; a row with a small \(|g|\) is already learnt. GOSS uses this.

3. Exclusive features

In sparse data (one-hot, bag of words), many columns are zero almost everywhere, and two such columns are rarely non-zero in the same row. They can safely share one column.

4. Leaf-wise (best-first) growth

Instead of completing a level, LightGBM finds the single leaf with the highest gain anywhere in the tree and splits that one. This gives lower loss for the same number of leaves, but the tree becomes deep and unbalanced.

4Histogram-based Split Finding

4.1The Problem with the Exact Greedy Algorithm

XGBoost's exact method, for one feature in one node:

  1. Sort all values of that feature (pre-sorted once, kept in memory).
  2. Scan left to right, keeping a running \(G_L,H_L\), and evaluate the gain at every possible threshold.

Cost per level: \(O(\#data\times\#feature)\) for the scan, and the memory holds the sorted indices plus the float values — typically two large arrays. On a dataset with 10 million rows this is very heavy.

4.2The Histogram Idea (derivation)

Step 1: Bin once, at the start.

For each feature, find 255 bin boundaries (by quantiles) and replace every float value by a bin index that fits in 1 byte. A float64 is 8 bytes, a uint8 is 1 byte → 8× less memory, and no sorted-index array is needed at all.

Step 2: Build the histogram of a node.

Go through the rows of the node once. For each row add its \(g_i\) and \(h_i\) into the bucket of its bin:

$$G_k=\sum_{i:\;\text{bin}(x_{ij})=k}g_i,\qquad H_k=\sum_{i:\;\text{bin}(x_{ij})=k}h_i,\qquad n_k=\text{count}$$

This costs \(O(\#data)\) per feature — one pass, no sorting.

Step 3: Find the split from the histogram only.

A candidate split "bin \(\le k\)" gives, by a running sum over bins:

$$G_L=\sum_{m\le k}G_m,\qquad H_L=\sum_{m\le k}H_m,\qquad G_R=G_P-G_L,\qquad H_R=H_P-H_L$$

and then the usual gain formula. This loop runs over 255 bins, not over millions of rows.

4.3The Histogram Subtraction Trick

This is the part interviewers like.

Every row of the parent goes either left or right, so for every bin \(k\):

$$G_k^{\text{parent}}=G_k^{\text{left}}+G_k^{\text{right}}\;\Longrightarrow\; G_k^{\text{right}}=G_k^{\text{parent}}-G_k^{\text{left}}$$
Key Insight

So we only build the histogram of the smaller child (fewer rows to scan) and get the bigger child's histogram for free by subtraction. Since the smaller child has at most half the rows, this roughly halves the work at every level.

4.4Does Binning Hurt Accuracy?

The split can only be placed on a bin boundary, so it is an approximate split. In practice the loss of accuracy is tiny, and the coarser threshold actually works as regularisation (it cannot cut between two nearly identical values just to fit noise). Lower max_bin = faster and more regularised; higher = slower and more exact.

5GOSS — Gradient-based One-Side Sampling

5.1The Idea

In AdaBoost every row carries a weight, so you know which rows matter. In gradient boosting there is no weight — so what tells us a row is important? The gradient.

  • Large \(|g_i|\): the model is still very wrong on this row → informative, keep it.
  • Small \(|g_i|\): the model already predicts this row well → it contributes almost nothing to the gain, and we can drop most of them.

Simply deleting all small-gradient rows would be wrong, because it changes the data distribution — the computed gain would no longer be an estimate of the true gain. GOSS fixes that with one constant.

5.2The Algorithm

Input: training rows with gradients g, sampling ratios a and b

1. Sort all n rows by |g| in decreasing order.
2. Set A  = the top  a*n  rows            (large gradient - keep ALL)
3. Set A' = the remaining (1-a)*n rows    (small gradient)
4. Set B  = a RANDOM sample of  b*n  rows taken from A'
5. Multiply the gradients (and Hessians) of the rows in B by (1-a)/b
6. Build the tree using only the rows A union B

Typical values: \(a=0.2\), \(b=0.1\) → the tree is built on \(0.2n+0.1n = 0.3n\) rows, i.e. about one third of the data.

5.3Derivation of the Constant \(\frac{1-a}{b}\)

Step 1: What we want.

The true gain needs the sum of gradients over all rows in a side of the split:

$$S_{\text{true}}=\sum_{i\in A_l}g_i+\sum_{i\in A'_l}g_i$$

The first part is exact (we kept all of \(A\)). The problem is the second part — we only have the sample \(B_l\subset A'_l\).

Step 2: Count how many rows each sampled row must represent.

The small-gradient group \(A'\) has \((1-a)n\) rows. From it we sampled \(bn\) rows. So each sampled row stands for

$$\frac{\text{size of the group}}{\text{size of the sample}}=\frac{(1-a)\,n}{b\,n}=\frac{1-a}{b}\quad\text{rows.}$$

Step 3: Apply the weight and check it is unbiased.

Give every sampled row the weight \(w=\frac{1-a}{b}\). Because \(B\) is a uniform random sample of \(A'\), the expected value of the weighted sum is

$$\mathbb{E}\!\left[\frac{1-a}{b}\sum_{i\in B_l}g_i\right]=\frac{1-a}{b}\cdot b\,n\cdot\overline{g}_{A'_l}=(1-a)\,n\cdot\overline{g}_{A'_l}=\sum_{i\in A'_l}g_i$$

which is exactly the quantity we were missing. So the estimate is unbiased.

Formula / Result: GOSS estimated gain
$$\tilde{V}_j(d)=\frac{1}{n}\left[\frac{\Big(\sum_{x_i\in A_l}g_i+\frac{1-a}{b}\sum_{x_i\in B_l}g_i\Big)^2}{n_l(d)} +\frac{\Big(\sum_{x_i\in A_r}g_i+\frac{1-a}{b}\sum_{x_i\in B_r}g_i\Big)^2}{n_r(d)}\right]$$

Step 4: Sanity check with numbers.

Take \(a=0.2,\;b=0.1\). Then \(w=\frac{1-0.2}{0.1}=\frac{0.8}{0.1}=8\). Makes sense: the small-gradient group holds 80% of the rows and we kept only 10%, so each kept row speaks for 8 rows.

Key Insight

GOSS is not plain random sampling. It keeps every important row and only samples the boring ones, then re-weights them so the gain stays unbiased. The LightGBM paper proves the approximation error shrinks as \(O(1/n)\), so on large datasets GOSS loses almost no accuracy while using about one third of the rows.

In the library this is boosting_type='goss'. The default is 'gbdt' (no sampling). A related option is bagging_fraction, which is ordinary random row sampling.

6EFB — Exclusive Feature Bundling

6.1The Observation

After one-hot encoding, a column like city_Delhi is 1 only for Delhi rows and 0 everywhere else. city_Pune is 1 only for Pune rows. These two columns are never non-zero in the same row — they are mutually exclusive. In such sparse data, most feature pairs behave this way.

If a bundle of such features is stored as one feature, the number of features drops a lot and the histogram cost \(O(\#data\times\#feature)\) becomes \(O(\#data\times\#bundle)\) — with no information lost.

6.2Sub-problem 1: Which features to bundle?

Build a graph: each feature is a vertex, and two vertices are joined by an edge if the two features conflict (are non-zero together) too often. Finding the minimum number of bundles is then graph colouring, which is NP-hard, so LightGBM uses a greedy approximation:

1. Count the conflicts for every pair; build the graph with weighted edges.
2. Sort the features by degree (most conflicting first).
3. For each feature in order:
       try to put it in an existing bundle whose total conflict
       stays below a tolerance gamma;
       if none fits, open a new bundle.

Allowing a small conflict rate \(\gamma\) (a few rows where both are non-zero) makes the bundles much smaller, and the accuracy loss is bounded by \(O\big((1-\gamma)^{-2/3}\big)\) in the paper — in short, a small \(\gamma\) is safe.

6.3Sub-problem 2: How to merge them?

The merged column must let the histogram still tell the two original features apart. The trick is an offset.

Formula / Result: Merging with offsets

Let feature \(A\) take values in \([0,10]\) and feature \(B\) in \([0,20]\). Add \(\text{offset}_A=10\) to \(B\):

$$x_{\text{bundle}}=\begin{cases}x_A & \text{if } x_A\neq 0\quad\text{(range } 1\text{–}10)\\[2pt] x_B+10 & \text{if } x_A=0,\;x_B\neq 0\quad\text{(range } 11\text{–}30)\\[2pt] 0 & \text{if both are } 0\end{cases}$$

Now bins 1–10 of the bundle mean "feature A had this value" and bins 11–30 mean "feature B had this value". A split inside either range still recovers the original feature exactly.

Key Insight

EFB is lossless for truly exclusive features. It is what makes LightGBM very strong on sparse, high-dimensional, one-hot encoded data.

8Categorical Features in LightGBM

LightGBM accepts categorical columns directly (categorical_feature=[...]), but its method is different from CatBoost — there is no target statistic and no ordering.

It uses Fisher's method for partitioning categories:

  1. For each category \(c\), compute \(\dfrac{\sum_{i\in c}g_i}{\sum_{i\in c}h_i}\).
  2. Sort the categories by that ratio.
  3. Find the best split on this sorted list, exactly like a numeric feature.

Cost is \(O(k\log k)\) for \(k\) categories instead of \(O(2^{k-1})\) for all possible subsets.

Caution

This is powerful but overfits on high-cardinality columns, because a category with 2 rows can get its own branch. Control it with min_data_per_group and cat_smooth, or just use CatBoost when the categorical columns are the main signal.

9.2Finding the Split from the Histogram (\(\lambda=0\))

Only 3 candidate splits exist (after bin 1, after bin 2, after bin 3) — we use running sums:

split\(G_L,H_L\)\(G_R,H_R\)Gain \(=\frac12\big[\frac{G_L^2}{H_L}+\frac{G_R^2}{H_R}-0\big]\)

Best split = after bin 2, i.e. CGPA \(\le 7\). Leaf values:

$$w_L=-\frac{G_L}{H_L+\lambda}=-\frac{8}{4}=-2,\qquad w_R=-\frac{-8}{4}=+2$$

9.3The Subtraction Trick in Action

The left child has rows 1–4 and the right child has rows 5–8. LightGBM scans only one of them (say the left, 4 rows) to build its histogram, and gets the right child's histogram as

$$\text{Hist}_{\text{right}}=\text{Hist}_{\text{parent}}-\text{Hist}_{\text{left}}$$

bin by bin, with no data scan at all.

9.4GOSS on the Same Data

Take \(a=0.25,\;b=0.25\), so \(w=\frac{1-0.25}{0.25}=3\).

  • Sort by \(|g|\): rows 1 (3), 8 (3), 2 (2), 3 (2), 6 (2), 7 (2), 4 (1), 5 (1).
  • Set \(A\) = top \(0.25\times 8=2\) rows → rows 1 and 8. Keep their gradients as they are.
  • Set \(B\) = random \(0.25\times 8=2\) rows from the other six → say rows 3 and 6. Their gradients become \(2\times 3=6\) and \(-2\times 3=-6\).
  • Build the tree on just these 4 rows with gradients \(\{+3,\,+6,\,-6,\,-3\}\).

The weighted sum is \(3+6-6-3=0\), the same as the true total \(G_P=0\) — the estimate stayed unbiased while using half the rows.

8Interview Questions & Answers

Q1. What is the difference between XGBoost, LightGBM and CatBoost?

All three are gradient boosting on decision trees, so the maths of boosting is identical. They differ in three things. Tree growth: XGBoost grows level-wise, LightGBM leaf-wise, CatBoost builds symmetric trees. Split finding: XGBoost uses exact or sketch-based search, LightGBM uses histograms plus GOSS and EFB, CatBoost uses histograms on symmetric levels. Special problem solved: LightGBM solves speed and memory, CatBoost solves categorical features and the bias of boosting.

Q2. Why is LightGBM faster than XGBoost?

Three reasons. It bins each feature into 255 buckets, so the split search is over bins, not rows, and the data fits in 1 byte per value. It uses the histogram subtraction trick, so one child's histogram is free. And GOSS trains on about a third of the rows while EFB reduces the number of features.

Q3. Explain GOSS.

Gradient-based One-Side Sampling. Rows with a large absolute gradient are still badly predicted, so they are informative; rows with a small gradient are already learnt. GOSS keeps all of the top \(a\%\) by \(|g|\) and randomly samples \(b\%\) of the rest, then multiplies the sampled rows' gradients by \(\frac{1-a}{b}\) so that the gain estimate stays unbiased. With \(a=0.2,b=0.1\) the factor is 8, because the small-gradient group is 80% of the data but only 10% was kept.

Q4. Explain EFB.

Exclusive Feature Bundling. In sparse data many features are never non-zero at the same time, for example one-hot columns. Such features are bundled into a single feature, which reduces the feature count without losing information. Choosing the bundles is a graph colouring problem solved greedily with a small allowed conflict rate, and merging is done by adding an offset so each original feature occupies its own range of bin values.

Q5. Leaf-wise vs level-wise — which is better?

Leaf-wise gives a lower loss for the same number of leaves, because it always splits the leaf with the highest gain. But the tree becomes deep and unbalanced, so it overfits on small data. Level-wise is more balanced and safer but wastes work on low-gain nodes. In LightGBM I control leaf-wise growth with num_leaves and min_data_in_leaf.

Q6. What is target leakage in categorical encoding?

When the target of a row is used to build that same row's feature. In the extreme case where every category is unique, mean encoding makes the feature equal to the target, so one split gives perfect training accuracy and random test accuracy. Even leave-one-out encoding leaks, because the row's own \(y\) is visibly subtracted out of the mean.

Q7. How does CatBoost handle categorical features?

With ordered target statistics. It picks a random permutation to act as artificial time, and the encoding of a row is computed using only the rows that appear before it, with a prior for smoothing. The row's own target is never used, so there is no leakage, and no data is wasted. It also creates feature combinations automatically, and uses one-hot encoding for very low-cardinality columns.

Q8. What is prediction shift and ordered boosting?

In ordinary boosting the residual of a row is computed from a model that was trained on that same row, so the residuals on training data are smaller than on unseen data. That bias is called prediction shift and it is of order \(1/n\), so it hurts small datasets most. CatBoost's ordered boosting computes each row's gradient from a supporting model trained only on the rows before it in the permutation, which makes the gradient unbiased.

Q9. What is an oblivious tree and why use it?

A tree where all nodes at the same depth use the same feature and threshold. Advantages: prediction is extremely fast, because the \(D\) comparisons build a \(D\)-bit index and the leaf value is a single array lookup; and the restricted structure acts as regularisation, which is why CatBoost works well out of the box. The disadvantage is less flexibility, so it may need more trees.

Q10. Which library would you choose for a dataset with many categorical columns?

CatBoost, because it encodes them internally without leakage and builds combinations automatically. LightGBM can take categorical columns too but overfits on high-cardinality ones, and XGBoost normally needs me to encode them myself, where I would have to be careful about leakage.

Q11. Why does LightGBM overfit on small datasets?

Because leaf-wise growth keeps splitting the single best leaf, so it can build a very deep branch that fits a handful of rows. On small data there are not enough rows to stop it. The fix is to lower num_leaves, raise min_data_in_leaf, set a max_depth, and use a smaller learning rate with more trees.

Q12. Does binning in LightGBM reduce accuracy?

Slightly, because the split can only be placed on a bin boundary, so it is approximate. In practice the loss is negligible and the coarse threshold acts as regularisation. max_bin controls the trade-off: smaller is faster and more regularised, larger is more exact.

Q13. What is the histogram subtraction trick?

Since every row of a parent node goes to exactly one child, the parent histogram is the sum of the two children's histograms, bin by bin. So LightGBM builds the histogram only for the smaller child and obtains the other by subtraction, which roughly halves the work at every level.

Q14. Is the gain formula different in the three libraries?

No. All three use the same second-order gain, \(\frac12\big[\frac{G_L^2}{H_L+\lambda}+\frac{G_R^2}{H_R+\lambda}-\frac{G_P^2}{H_P+\lambda}\big]-\gamma\), and the same leaf value \(w=-\frac{G}{H+\lambda}\). What differs is which candidate splits are evaluated and which node gets split next.

Q15. Why do all three beat a single deep decision tree?

A single deep tree has low bias but very high variance. Boosting builds many shallow trees where each one corrects the errors of the previous ones, and the learning rate keeps every step small. So the bias comes down gradually while the variance stays controlled by the shallow depth, the shrinkage and the regularisation terms.

Q16. In one sentence, when do you use each?

LightGBM when the data is large and speed matters, CatBoost when categorical features dominate or the dataset is small, and XGBoost as a reliable general default with the biggest ecosystem.

9Final Mind Map

Last line to remember

Boosting itself is the same in all three. XGBoost made it regularised, LightGBM made it fast, CatBoost made it honest.
