CatBoost & LightGBM — Revision Guide

Only what is asked in interviews — with pictures

Part 1: CatBoost  ·  Part 2: LightGBM  ·  Part 3: Compare with XGBoost

Read this first — the whole topic in 4 lines

All three are Gradient Boosting on Decision Trees. The boosting maths is the same in all three (same gain, same leaf value). They differ in only three things:

1. How the tree finds a split.   2. How the tree grows.   3. Which extra problem they fix.

LightGBM fixes speed. CatBoost fixes categorical features and bias.

Part 1

CatBoost

Categorical Boosting — Yandex, 2017

1All Formulas in One Place

A. Categorical encoding (the main idea of CatBoost)

Plain target encoding (leaks the answer):

$$\hat{x}_i=\frac{\sum_{j=1}^{n}\mathbb{1}\{x_j=x_i\}\cdot y_j+a\,P}{\sum_{j=1}^{n}\mathbb{1}\{x_j=x_i\}+a}$$

Ordered Target Statistic (what CatBoost uses):

$$\hat{x}_i=\frac{\sum_{x_j\in\mathcal{D}_i}\mathbb{1}\{x_j=x_i\}\cdot y_j+a\,P}{\sum_{x_j\in\mathcal{D}_i}\mathbb{1}\{x_j=x_i\}+a}, \qquad \mathcal{D}_i=\{\text{rows before } i\}$$

In words: (sum of y in that category + a × prior) / (count + a), but counting only the rows that came before this row. \(P\) = mean of \(y\), \(a\) = smoothing.

B. Ordered boosting and the tree

Normal boosting gradient (biased): uses \(F^{t-1}\), which was trained on row \(i\) too.

Ordered boosting gradient (unbiased):

$$g_i=-\left.\frac{\partial L(y_i,s)}{\partial s}\right|_{s=M_{\sigma(i)-1}(x_i)}\qquad(M \text{ never saw row } i)$$

Leaf value and gain (same as XGBoost):

$$w_j=-\frac{G_j}{H_j+\lambda},\qquad \text{Gain}=\frac{1}{2}\left[\frac{G_L^2}{H_L+\lambda}+\frac{G_R^2}{H_R+\lambda}-\frac{G_P^2}{H_P+\lambda}\right]$$

Oblivious tree leaf number: \(\;\text{leaf}(x)=\sum_{d=0}^{D-1}2^{\,d}\cdot\mathbb{1}\{x^{f_d}\gt t_d\}\)

2What is CatBoost?

CatBoost = Categorical + Boosting, made by Yandex in 2017. The boosting part is normal. It is special because it fixes two problems:

ProblemWhat goes wrongCatBoost's fix
1. Categorical featuresOne-hot blows up memory. Target encoding leaks the answer.Ordered Target Statistics
2. Prediction shiftThe residual of a row is found using a model that already saw that row → model is biased.Ordered Boosting
The one-line answer

"CatBoost is gradient boosting that handles categorical columns itself using ordered target statistics, removes the bias of boosting using ordered boosting, and builds symmetric trees which make prediction very fast."

3Problem 1: Categorical Features

3.1Why the normal methods fail

So target encoding is the right idea, but it must be made safe. First, add smoothing so a rare category does not get a noisy value:

Formula / Result: smoothed target statistic
$$\hat{x}_i=\frac{(\text{sum of } y \text{ in the category})+a\,P}{(\text{count of the category})+a}$$

If the count is big, the prior \(P\) does not matter. If the count is 1 or 2, the value stays near the prior. Same idea as Laplace smoothing.

3.2Why plain target encoding leaks (derivation)

Take the worst case: a column where every row has its own category (like order-id). Put \(a=0\). For row \(i\), the only row in that category is row \(i\) itself:

$$\hat{x}_i=\frac{1\cdot y_i}{1}=y_i$$

The feature has become the target. See what happens:

Figure 3.1 — Target leakage: perfect on train, useless on test.

3.3Leave-one-out also leaks (derivation)

Obvious idea: for row \(i\), use all rows except row \(i\).

Now take the opposite case: one single category for all \(n\) rows, \(y\) is 0/1, and \(n^{+}\) rows have \(y=1\). With \(a=0\):

$$\hat{x}_i=\frac{n^{+}-y_i}{n-1} \;\Rightarrow\; \begin{cases} y_i=0:&\hat{x}_i=\dfrac{n^{+}}{n-1}\quad(\text{bigger})\\[6pt] y_i=1:&\hat{x}_i=\dfrac{n^{+}-1}{n-1}\quad(\text{smaller}) \end{cases}$$
Key Insight

The two classes get two different numbers, so one split again separates them perfectly — even though the column is a single constant category with zero information! The row's own \(y\) is still visible, because it subtracts itself out of the mean. Any method where the encoding of row \(i\) depends on \(y_i\) — even by subtraction — leaks.

3.4The fix: Ordered Target Statistics

CatBoost copies the idea of online learning: if data arrives one row at a time, you can never cheat, because the future has not happened yet. Our data has no time column, so CatBoost makes one up — a random permutation.

Figure 3.2 — Ordered Target Statistics: look only at the past.
Formula / Result: Ordered Target Statistic
$$\hat{x}_i=\frac{\sum_{x_j\in\mathcal{D}_i}\mathbb{1}\{x_j=x_i\}\cdot y_j+a\,P}{\sum_{x_j\in\mathcal{D}_i}\mathbb{1}\{x_j=x_i\}+a},\qquad \mathcal{D}_i=\{x_j:\sigma(j)\lt\sigma(i)\}$$

Small example — prior \(P=0.5\), \(a=1\), order = 1,2,3,4,5:

#cityyhistory of same citycalculationvalue

Look at row 4: its own \(y=0\) does not pull the value down. That is the leak removed.

Feature combinations (one more CatBoost trick)

city alone and device alone may be weak, but Delhi + iPhone can be strong. CatBoost joins categorical columns greedily during tree building, treats the pair as one new category, and encodes it with ordered TS. You get interaction features for free.

4Problem 2: Prediction Shift → Ordered Boosting

This problem exists in every boosting library, even with no categorical columns.

Figure 4.1 — Prediction shift and how ordered boosting removes it.
Key Insight

The gradient on a training row is not from the same distribution as on a test row. This gap is called prediction shift. Its size is about \(1/n\), so it hurts small datasets most. It is the same disease as target leakage, one level higher: there the feature used \(y_i\), here the residual uses \(y_i\).

4.1How ordered boosting works

Interview point

boosting_type='Ordered' → full scheme, better on small data, slower. boosting_type='Plain' → normal boosting (still with ordered TS for categories), default on big data because the \(1/n\) bias is then very small.

5Oblivious (Symmetric) Trees

In XGBoost and LightGBM, every node picks its own split. In CatBoost, the whole level uses one split.

Figure 5.1 — Oblivious tree: the leaf number is a binary number built from the splits.
PointReason
Very fast prediction\(D\) comparisons give a \(D\)-bit index, and the answer is one array lookup. No branching → CPU friendly.
Acts as regularisationFar fewer possible tree shapes, so it cannot chase noise. This is why CatBoost works well without tuning.
DisadvantageLess flexible, so it sometimes needs more trees to reach the same accuracy.

6Quick Numeric Example

4 rows, predict package from city (categorical) and CGPA. \(\eta=0.1\), \(\lambda=0\), \(a=1\).

#cityCGPAyordered TS of cityresidual \(r=y-F_0\)
1Delhi8.06(0+5)/(0+1) = 5.00+1
2Pune7.04(0+5)/(0+1) = 5.00−1
3Delhi9.08(6+5)/(1+1) = 5.50+3
4Pune6.02(4+5)/(1+1) = 4.50−3

Base model: \(F_0=\bar{y}=(6+4+8+2)/4=5\), prior \(P=5\). Now try the split CGPA < 7.5. Left = rows 2, 4 and Right = rows 1, 3. With squared loss \(G=-\sum r\) and \(H=\) count:

$$\text{Gain}=\frac{1}{2}\left[\frac{4^2}{2}+\frac{(-4)^2}{2}-\frac{0^2}{4}\right]=8 \qquad\text{vs. the city split, which gives } 6$$

CGPA wins, so the whole level uses CGPA < 7.5. Leaf values and update:

$$w_{\text{left}}=-\frac{4}{2}=-2,\qquad w_{\text{right}}=-\frac{-4}{2}=+2,\qquad F_1=5+0.1\,w$$

Rows 1, 3 become 5.2 and rows 2, 4 become 4.8. New residuals: \(\{0.8,-0.8,2.8,-2.8\}\) — smaller than before. Next round uses a new permutation, so the city values change slightly — that is the built-in averaging.

Part 2

LightGBM

Light Gradient Boosting Machine — Microsoft, 2017

1All Formulas in One Place

A. Same gain and leaf value as XGBoost
$$w_j=-\frac{G_j}{H_j+\lambda},\qquad \text{Gain}=\frac{1}{2}\left[\frac{G_L^2}{H_L+\lambda}+\frac{G_R^2}{H_R+\lambda}-\frac{G_P^2}{H_P+\lambda}\right]-\gamma$$
B. The three speed tricks

1. Histogram: every value becomes a bin number (255 bins). For each bin store \(\sum g\), \(\sum h\), count.

$$\text{Hist}_{\text{sibling}}=\text{Hist}_{\text{parent}}-\text{Hist}_{\text{child}}\quad(\text{subtraction trick})$$

2. GOSS: keep the top \(a\%\) rows by \(|g|\), sample \(b\%\) of the rest, and multiply those sampled rows by

$$\text{weight}=\frac{1-a}{b}$$

3. EFB: merge two sparse features into one using an offset.

$$x_{\text{bundle}}=\begin{cases}x_A & \text{if } x_A\neq 0\\ x_B+\max(x_A) & \text{if } x_A=0\end{cases}$$

2What is LightGBM?

"Light" means fast to train and small in memory. The accuracy is about the same as XGBoost — the contribution is speed. It does this with four ideas:

The one-line answer

"LightGBM is gradient boosting made fast. It puts features into histogram bins, uses GOSS to keep only the informative rows, uses EFB to merge sparse columns, and grows trees leaf-wise. Same accuracy as XGBoost, much less time and memory."

3Trick 1: Histogram Split Finding

The problem. XGBoost's exact method sorts every feature and checks every possible threshold. Cost = \(O(\#data\times\#feature)\), and it must keep the sorted indexes in memory. On 1 crore rows this is very heavy.

The idea. Put the values into 255 buckets once, at the start. Then the tree only has to try 254 thresholds instead of millions.

Figure 3.1 — Histogram binning.
StepXGBoost (exact)LightGBM (histogram)
Preparesort every feature: \(O(n\log n)\)bin every feature once: \(O(n)\)
Find best split\(O(\#data\times\#feature)\)\(O(\#bin\times\#feature)\)

3.1The histogram subtraction trick

Every row of the parent goes either left or right. So for every bin:

$$\text{Hist}_{\text{parent}}=\text{Hist}_{\text{left}}+\text{Hist}_{\text{right}} \;\Longrightarrow\;\text{Hist}_{\text{right}}=\text{Hist}_{\text{parent}}-\text{Hist}_{\text{left}}$$
Figure 3.2 — The subtraction trick: build one child, get the other for free.
Does binning hurt accuracy?

Slightly — the split can only sit on a bin edge, so it is approximate. But the loss is tiny, and the coarse threshold works as regularisation (it cannot cut between two almost-equal values just to fit noise). max_bin controls this: smaller = faster, bigger = more exact.

4Trick 2: GOSS (Gradient-based One-Side Sampling)

The idea. A row with a big \(|g|\) is still badly predicted, so it is useful. A row with a small \(|g|\) is already learnt, so it adds almost nothing. Keep all the useful rows and throw away most of the boring ones.

Figure 4.1 — GOSS keeps the important rows and re-weights the sampled ones.

4.1Why the weight is \(\frac{1-a}{b}\) (derivation)

Step 1. What we need.

The true gain needs the sum of gradients of all rows on a side. Set \(A\) is complete, so only the small-gradient part is missing.

Step 2. How many rows does one sampled row stand for?

The small-gradient group has \((1-a)n\) rows. We kept \(bn\) of them. So each kept row must represent

$$\frac{(1-a)\,n}{b\,n}=\frac{1-a}{b}\ \text{ rows.}$$

Step 3. Check that it is unbiased.

Because the sample is random and uniform,

$$\mathbb{E}\!\left[\frac{1-a}{b}\sum_{i\in B}g_i\right]=\frac{1-a}{b}\cdot b\,n\cdot\overline{g}=(1-a)\,n\cdot\overline{g}=\sum_{i\in A'}g_i$$

which is exactly the missing sum. So the estimated gain is unbiased.

Key Insight

GOSS is not plain random sampling. Plain sampling would change the data distribution and make the gain wrong. GOSS keeps every important row, samples only the boring ones, and then fixes the maths with one constant.

5Trick 3: EFB (Exclusive Feature Bundling)

The observation. After one-hot encoding, city_Delhi is 1 only for Delhi rows and city_Pune is 1 only for Pune rows. They are never 1 at the same time. Such columns can share one column.

Figure 5.1 — EFB merges exclusive features using an offset.

Two sub-problems:

  • Which features to bundle? Make a graph: features are points, and an edge means "these two clash too often". Grouping them is graph colouring, which is NP-hard, so LightGBM does it greedily and allows a small clash rate \(\gamma\).
  • How to merge? Add an offset so each feature gets its own range of bin values, as in the picture.

7Categorical Features & Key Settings

LightGBM takes categorical columns directly, but in a different way from CatBoost — no target statistic, no ordering. It uses Fisher's method:

  1. For each category compute \(\dfrac{\sum g}{\sum h}\).
  2. Sort the categories by that number.
  3. Split the sorted list like a normal numeric feature — cost \(O(k\log k)\) instead of \(O(2^{k-1})\).

Caution: this overfits on high-cardinality columns, because a category with 2 rows can get its own branch. Use cat_smooth and min_data_per_group, or use CatBoost instead.

LightGBM overfits on small data (under roughly 10,000 rows) because leaf-wise growth builds very specific deep branches. Fix: lower num_leaves, raise min_data_in_leaf, set a max_depth.

8Interview Questions & Answers

Q1. Difference between XGBoost, LightGBM and CatBoost?

All three are gradient boosting on trees, so the boosting maths is the same. They differ in three things. Tree growth: XGBoost level-wise, LightGBM leaf-wise, CatBoost symmetric. Split finding: XGBoost exact or sketch, LightGBM histogram + GOSS + EFB, CatBoost histogram with one split per level. Extra problem solved: LightGBM solves speed, CatBoost solves categorical features and bias.

Q2. Why is LightGBM faster than XGBoost?

Three reasons. It bins values into 255 buckets, so the split search is over bins not rows, and each value takes 1 byte instead of 8. The subtraction trick gives one child's histogram free. And GOSS trains on about a third of the rows while EFB reduces the number of columns.

Q3. Explain GOSS.

Rows with a big gradient are still badly predicted, so they are informative; rows with a small gradient are already learnt. GOSS keeps all the top \(a\%\) by \(|g|\), randomly samples \(b\%\) of the rest, and multiplies those sampled rows by \(\frac{1-a}{b}\) so the gain stays unbiased. With \(a=0.2,b=0.1\) the factor is 8, because the small-gradient group is 80% of the data but only 10% was kept.

Q4. Explain EFB.

In sparse data many columns are never non-zero at the same time, like one-hot columns. EFB bundles them into a single column, which cuts the feature count with no information lost. Choosing the bundles is graph colouring, solved greedily; merging is done by adding an offset so each original feature keeps its own range of values.

Q5. Leaf-wise or level-wise — which is better?

Leaf-wise gives lower loss for the same number of leaves, because it always splits the best leaf. But the tree becomes deep and unbalanced, so it overfits on small data. I control it with num_leaves and min_data_in_leaf.

Q6. What is target leakage in categorical encoding?

When a row's own target is used to build that row's feature. If every category is unique, mean encoding makes the feature equal to the target, so one split gives 100% training accuracy and random test accuracy. Even leave-one-out leaks, because the row's own \(y\) is visibly subtracted from the mean.

Q7. How does CatBoost handle categorical features?

With ordered target statistics. It takes a random permutation as a fake time order, and encodes a row using only the rows before it, with a prior for smoothing. The row's own target is never used, so there is no leakage, and no data is wasted. It also builds feature combinations automatically.

Q8. What is prediction shift and ordered boosting?

In normal boosting a row's residual comes from a model that was trained on that same row, so training residuals are smaller than they should be and the model is biased. The bias is about \(1/n\), so small data suffers most. Ordered boosting computes each row's gradient from a supporting model trained only on the earlier rows, which makes it unbiased.

Q9. What is an oblivious tree and why use it?

A tree where every node at the same depth uses the same feature and threshold. The \(D\) comparisons give a \(D\)-bit index and the leaf value is one array lookup, so prediction is very fast. The restricted shape also acts as regularisation, which is why CatBoost works well with default settings. The downside is less flexibility, so it may need more trees.

Q10. Which library for a dataset with many categorical columns?

CatBoost, because it encodes them internally without leakage and makes combinations automatically. LightGBM accepts them too but overfits on high-cardinality ones, and XGBoost needs me to encode them myself, where I would have to be careful about leakage.

Q11. Why does LightGBM overfit on small data?

Because leaf-wise growth keeps splitting the single best leaf, so it can build a deep branch that fits only a few rows. The fix is lower num_leaves, higher min_data_in_leaf, a max_depth limit, and a smaller learning rate with more trees.

Q12. What is the histogram subtraction trick?

Every row of a parent goes to exactly one child, so the parent histogram equals the sum of the two children's histograms. LightGBM builds the histogram only for the smaller child and gets the other one by subtraction, which roughly halves the work at every level.

Q13. Is the gain formula different in the three libraries?

No. All three use \(\frac12\big[\frac{G_L^2}{H_L+\lambda}+\frac{G_R^2}{H_R+\lambda}-\frac{G_P^2}{H_P+\lambda}\big]\) and the leaf value \(w=-\frac{G}{H+\lambda}\). What differs is which splits are tried and which node is split next.

Q14. Does binning reduce accuracy in LightGBM?

Slightly, because the split must sit on a bin edge, so it is approximate. In practice the loss is very small and the coarse threshold acts as regularisation. max_bin controls the trade-off.

Q15. In one sentence, when do you use each?

LightGBM when the data is large and speed matters, CatBoost when categorical columns dominate or the dataset is small, and XGBoost as a reliable default with the biggest ecosystem.

Last line to remember

Boosting itself is the same in all three. XGBoost made it regularised, LightGBM made it fast, CatBoost made it honest.
